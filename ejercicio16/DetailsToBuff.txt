Ruta de Aprendizaje: De Código Funcional a Código Profesional y Eficiente
1. El Algoritmo: El Corazón de la Solución
    Concepto Clave a Mejorar: Complejidad Algorítmica.

    Tu solución actual tiene una complejidad aproximada de O(n²), donde 'n' es la longitud de la
    cadena. Esto ocurre porque dentro de tu bucle for (que recorre la cadena),
    utilizas substring.includes(). El método includes() tiene que recorrer, en el peor de los casos,
    toda la subcadena para encontrar un carácter. Un bucle dentro de otro bucle es una señal de una 
    posible ineficiencia.

    El Siguiente Nivel: La Técnica de la "Ventana Deslizante" (Sliding Window)
    Este es el patrón de algoritmo ideal para este tipo de problemas. Permite resolverlo en tiempo
    lineal, O(n), lo cual es muchísimo más rápido para cadenas largas.

    ¿Cómo funciona? Imagina dos punteros, inicio y fin, que forman una "ventana" sobre la cadena.
    Esta ventana representa tu subcadena actual sin caracteres repetidos.
    El puntero fin avanza hacia la derecha, expandiendo la ventana.
    Con cada avance, se verifica si el nuevo carácter ya está en la ventana.
    Si no está, la ventana es válida. Se actualiza la longitud máxima si es necesario.
    Si sí está, la ventana ya no es válida. Se mueve el puntero inicio hacia la derecha,
    encogiendo la ventana, hasta que el carácter repetido quede fuera.

    ¿Qué estudiar para implementarlo?
    Estructuras de Datos Eficientes:
        Para saber qué caracteres hay en la "ventana" de forma instantánea (en tiempo O(1)),
        no se usa includes(). Se usan Set o Map.
    Set:
        Almacena valores únicos. set.has(char) es una operación instantánea para verificar si un
        carácter existe. set.add(char) y set.delete(char) también son instantáneas.
    Map: 
        Almacena pares clave-valor. Es útil si necesitas guardar no solo el carácter, sino también
        su última posición (índice).

2. Estructura y Claridad del Código (Clean Code)
    Concepto Clave a Mejorar: Principio de Responsabilidad Única 
        (Single Responsibility Principle - SRP) y Nombres Descriptivos.
    Un desarrollador Senior separa las responsabilidades. Tu código actual mezcla la lógica del DOM
        (leer de un input, escribir en un span) con la lógica del algoritmo.
    El Siguiente Nivel: Funciones Puras y Desacopladas
    Crea una Función Pura para el Algoritmo:
    La lógica principal debería estar en una función que solo haga una cosa: recibir una cadena
        de texto y devolver la longitud de la subcadena más larga. Por ejemplo: functio
         findLongestSubstringLength(str) { ... }.
    Esta función no debe saber nada sobre inputs, buttons o spans. Esto la hace reutilizable y
        fácil de probar de forma aislada.
    El Event Listener solo debe ser un Coordinador:
    El código dentro de calcBtn.addEventListener debe ser mínimo:
    Obtener el valor del input.
    Llamar a tu función de algoritmo (findLongestSubstringLength).
    Tomar el resultado y mostrarlo en el DOM.
    Nombres Descriptivos:
    El nombre past_function es muy ambiguo. No describe lo que hace la función. Un buen nombre
        sería manejarCaracterRepetido o reiniciarSubcadenaDesde.
    La variable A en esa función debería llamarse subcadenaActual o algo similar para que el código
        sea auto-explicativo.



Resumen de Tareas para tu Crecimiento:

1.- Estudia a fondo el patrón "Sliding Window". Busca problemas similares en plataformas como
    LeetCode o HackerRank (por ejemplo, "Longest Substring Without Repeating Characters").

2.- Domina las estructuras de datos Set y Map en JavaScript. Comprende cuándo y por qué usarlas
    para optimizar tus algoritmos (principalmente para búsquedas, inserciones y eliminaciones en tiempo O(1)).

3.- Practica el Principio de Responsabilidad Única (SRP). Siempre que escribas código, pregúntate:
    "¿Esta función está haciendo más de una cosa?". Separa la lógica de negocio/algoritmos de la lógica de la interfaz.

4.- Adopta el hábito de escribir código limpio (Clean Code).
    Usa nombres de variables y funciones que describan su propósito.
    El código debe ser fácil de leer para otro programador (¡o para ti mismo en el futuro!).
